# Parity fixture generators

`test/fixtures/` holds four ground-truth files. All four are generated, never hand-edited,
and all four come from canonical Uniswap v4-core.

| Fixture | Cases | Generated by |
|---|---|---|
| `positions.json` | 20 | lp-terminal `engine/build_parity_fixtures.py` (real Robinhood Chain events) |
| `tick-sweep.json` | 477 | `test/Sweep.t.sol::test_EmitTickSweep` |
| `delta-sweep.json` | 280 | `test/Sweep.t.sol::test_EmitDeltaSweep` |
| `boundary-sweep.json` | 216 | `test/Sweep.t.sol::test_EmitBoundarySweep` |

## Why the sweeps exist

`positions.json` alone is not sufficient to pin the port. Its 20 positions are real, but
their asserted amounts either use full-range bounds (MIN/MAX tick) or take `sqrtPriceX96`
directly from the event, so the per-bit multipliers inside `getSqrtPriceAtTick` are barely
exercised. A corrupted multiplier — verified to change the result at 6,898 of 18,295 ticks
— passes all 20 fixtures. It also contains no case where the price sits strictly inside a
tick equal to a range bound, which is the only place `tick < tickLower` and
`tick <= tickLower` differ, so that slip survives it too.

The sweeps close both holes by asserting the tick, delta and branch-split functions
directly against v4-core across their domains.

## Regenerating

```sh
PEAPOD_LP_TERMINAL=~/lp-terminal ./generate.sh
npm test
```

Run `./generate.sh`, not `forge test` directly — remappings are resolved at run time and
passed on the command line, so a bare `forge test` has no imports and will fail.

### Paths

Nothing here hardcodes a checkout location. `generate.sh` resolves every dependency from
the environment and refuses to guess:

| Variable | Required | Meaning |
|---|---|---|
| `PEAPOD_LP_TERMINAL` | yes* | lp-terminal checkout; supplies v4-core and forge-std as submodules plus `PoolMathHarness.sol` |
| `PEAPOD_V4_CORE` | no | override: a v4-core checkout's `src/` |
| `PEAPOD_FORGE_STD` | no | override: a forge-std checkout's `src/` |
| `PEAPOD_POOL_MATH` | no | override: the directory holding `PoolMathHarness.sol` |

\* unless all three overrides are set, for when those dependencies no longer live inside
lp-terminal.

Each dependency is validated by a file the generator actually imports, so an uninitialised
submodule fails with that path named rather than inside solc. Requires Foundry on `PATH`.

Regeneration is deterministic: re-running against an unchanged v4-core reproduces all three
sweeps byte-for-byte.

## What is not regenerated here

`positions.json`. It is built in lp-terminal from live chain events
(`uv run python engine/build_parity_fixtures.py`, needs an archive RPC) and copied here
byte-for-byte, so that the file peapod asserts against is the same file
`contracts/test/LiquidityParity.t.sol` asserts against v4-core.

## Known fragility

These fixtures are committed, so `npm test` never needs this script — the engine stays
verifiable with no Foundry, no submodules and no lp-terminal. The script is only needed to
*re-verify* after v4-core or the port changes. If lp-terminal is ever retired, vendor
v4-core into peapod directly as a submodule and point `PEAPOD_V4_CORE` at it; nothing else
here has to change.
