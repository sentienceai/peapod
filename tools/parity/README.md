# Parity fixture generators

`test/fixtures/` holds three ground-truth files. All three are generated, never
hand-edited, and all three come from canonical Uniswap v4-core.

| Fixture | Cases | Generated by |
|---|---|---|
| `positions.json` | 20 | lp-terminal `engine/build_parity_fixtures.py` (real Robinhood Chain events) |
| `tick-sweep.json` | 477 | `Sweep.t.sol::test_EmitTickSweep` |
| `delta-sweep.json` | 280 | `Sweep.t.sol::test_EmitDeltaSweep` |

## Why the sweeps exist

`positions.json` alone is not sufficient to pin the port. Its 20 positions are real, but
their asserted amounts either use full-range bounds (MIN/MAX tick) or take `sqrtPriceX96`
directly from the event, so the per-bit multipliers inside `getSqrtPriceAtTick` are barely
exercised. A corrupted multiplier — verified to change the result at 6,898 of 18,295 ticks
— passes all 20 fixtures. The sweeps close that hole by asserting the tick and delta
functions directly against v4-core across the whole domain.

## Regenerating the sweeps

Requires Foundry and a checkout of lp-terminal with its `v4-core` submodule. The
remappings in `foundry.toml` point at that checkout; edit them if it lives elsewhere.

```sh
cd tools/parity
forge test --match-contract SweepTest
mv tick-sweep.json delta-sweep.json ../../test/fixtures/
```

`positions.json` is regenerated in lp-terminal (`uv run python engine/build_parity_fixtures.py`)
and copied here byte-for-byte; it needs an archive RPC, so it is not part of a routine run.
